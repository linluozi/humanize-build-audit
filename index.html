The bug worth finding

scripts/generate-translation-binaries.sh has no shebang. GitHub's default shell on Windows is pwsh, and pwsh does not execute a .sh file: it exits 0 having done nothing. The script that compiles the translation catalogs therefore never ran on Windows.

tests/test_i18n.py wraps every locale assertion in pytest.skip() when a catalog is missing, so the missing catalogs surfaced as skips, never as failures. Linux and macOS reported 856 passed; the nine Windows cells reported 744 passed, 112 skipped and were marked green.

The fix has two halves, and both are required. Install gettext so msgfmt exists, and run the script under bash so it is executed at all. A new step then fails the job if fewer than 36 catalogs were produced, so this cannot silently regress.
